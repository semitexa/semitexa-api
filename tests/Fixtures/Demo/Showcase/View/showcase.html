Semitexa API — interactive showcase

Six live endpoints demonstrating the semitexa-api request pipeline: #[ExternalApi] Payload → Handler → Resource → JSON renderer → X-Api-Version header decorator. Errors raised by handlers (NotFoundException, ValidationException) are formatted by ExternalApiExceptionMapper into a consistent machine envelope.

Article data is held in an in-memory store inside the package (InMemoryArticleRepository) and resets when the worker process restarts. Every "Run" button below issues a real fetch() against this server.

Operations

  1. GET /api/v1/demo/articles — collection
  2. GET /api/v1/demo/articles/{id} — single resource
  3. POST /api/v1/demo/articles — create
  4. PUT /api/v1/demo/articles/{id} — full replacement
  5. PATCH /api/v1/demo/articles/{id} — partial update
  6. DELETE /api/v1/demo/articles/{id} — idempotent delete

1. GET collection

List all demo articles. Demonstrates query-string filtering and a response envelope with both data (the collection) and meta (counts).

GET /api/v1/demo/articles v1
Implementation: ListArticlesPayload · ListArticlesHandler · ArticleCollectionResource

2. GET single resource

Fetch one article by id. A missing id raises NotFoundException, which the mapper renders as a 404 with the machine envelope (error.code = "not_found").

GET /api/v1/demo/articles/{id} v1
Implementation: GetArticlePayload · GetArticleHandler · ArticleResource

3. POST — create

Create a new article. Empty title raises ValidationException (422) with the field errors merged into error.context.errors.

POST /api/v1/demo/articles v1 application/json
Implementation: CreateArticlePayload · CreateArticleHandler · ArticleResource.created()

4. PUT — full replacement

Replace every mutable field. Missing title or body is a validation error.

PUT /api/v1/demo/articles/{id} v1 application/json
Implementation: ReplaceArticlePayload · ReplaceArticleHandler · ArticleResource

5. PATCH — partial update

Send only the fields you want to change. Sending an empty body raises a validation error so callers cannot accidentally PATCH nothing.

PATCH /api/v1/demo/articles/{id} v1 application/json
Implementation: PatchArticlePayload · PatchArticleHandler · ArticleResource

6. DELETE — idempotent

Delete by id. Returns 204 No Content on success and when the id was already missing — DELETE is idempotent.

DELETE /api/v1/demo/articles/{id} v1
Implementation: DeleteArticlePayload · DeleteArticleHandler · ArticleDeletedResource

What this page demonstrates: opt-in #[ExternalApi] activation, the consistent machine error envelope ({"error":{"code","message","context","request_id","docs_url"}}), X-Api-Version response header, and idempotent versus non-idempotent verb semantics.

Out of scope (separate epic): content negotiation, JSON-LD, HAL+JSON, and HTML representation switching are tracked as a follow-up — the current package is JSON-only by design.
